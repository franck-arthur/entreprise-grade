# Internationalisation (i18n)

L'application supporte l'internationalisation complète côté backend et frontend, avec support de l'anglais et du français.

---

## Backend (Spring Boot)

### Configuration

L'internationalisation est configurée dans `InternationalizationConfig.java` :

- **MessageSource** : Charge les messages depuis `src/main/resources/i18n/messages*.properties`
- **LocaleResolver** : Résout la locale depuis l'en-tête HTTP `Accept-Language`
- **Locales supportées** : `en` (anglais), `fr` (français)
- **Locale par défaut** : `en`

### Fichiers de Messages

```
backend/src/main/resources/i18n/
├── messages.properties        # Messages par défaut (anglais)
├── messages_en.properties     # Messages anglais
└── messages_fr.properties     # Messages français
```

### Utilisation dans le Code

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    private final MessageSource messageSource;

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleException(...) {
        Locale locale = LocaleContextHolder.getLocale();
        String message = messageSource.getMessage("error.not.found", null, locale);
        // ...
    }
}
```

### Validation avec Messages i18n

```java
public class CreateUserRequest {
    @NotBlank(message = "{validation.user.username.required}")
    @Size(min = 3, max = 50, message = "{validation.user.username.size}")
    private String username;
}
```

### Test avec Différentes Locales

```bash
# Requête en anglais
curl -H "Accept-Language: en-US" http://localhost:8080/api/v1/users/invalid-id

# Requête en français
curl -H "Accept-Language: fr-FR" http://localhost:8080/api/v1/users/invalid-id
```

## Frontend (Angular)

### Configuration

L'internationalisation utilise **ngx-translate** :

- **Service** : `LanguageService` gère la langue courante
- **Fichiers de traduction** : `src/assets/i18n/*.json`
- **Locales supportées** : `en` (anglais), `fr` (français)
- **Locale par défaut** : `en`
- **Persistence** : La langue est sauvegardée dans localStorage

### Fichiers de Traduction

```
frontend/src/assets/i18n/
├── en.json    # Traductions anglaises
└── fr.json    # Traductions françaises
```

### Structure des Traductions

```json
{
  "common": {
    "welcome": "Welcome",
    "loading": "Loading...",
    "save": "Save"
  },
  "auth": {
    "login": "Login",
    "username": "Username",
    "password": "Password"
  },
  "users": {
    "title": "User Management",
    "create_user": "Create User"
  }
}
```

### Utilisation dans les Composants

```typescript
import { TranslateModule } from '@ngx-translate/core';

@Component({
  imports: [TranslateModule],
  template: `
    <h1>{{ 'users.title' | translate }}</h1>
    <p>{{ 'dashboard.welcome_message' | translate: {username: user.name} }}</p>
  `
})
export class MyComponent {}
```

### Changement de Langue Programmatique

```typescript
import { LanguageService } from '@app/core/services/language.service';

constructor(private languageService: LanguageService) {}

changeLanguage(lang: string) {
  this.languageService.setLanguage(lang);
}
```

### Sélecteur de Langue

Le composant `LanguageSelectorComponent` est disponible :

```html
<app-language-selector></app-language-selector>
```

Il est déjà intégré dans le header de l'application.

## Communication Backend-Frontend

### Flux d'Internationalisation

1. **Frontend** : L'utilisateur sélectionne une langue
2. **Storage** : La langue est sauvegardée dans localStorage
3. **HTTP Request** : L'en-tête `Accept-Language` est ajouté automatiquement
4. **Backend** : Le backend résout la locale et retourne les messages traduits
5. **Frontend** : Les messages du backend sont affichés tels quels

### Interceptor HTTP

Le `languageInterceptor` ajoute automatiquement l'en-tête :

```typescript
// Exemple : langue française sélectionnée
// L'intercepteur ajoute : Accept-Language: fr-FR
```

### Affichage des Erreurs Backend

Les erreurs du backend sont déjà internationalisées :

```typescript
// Le backend retourne selon Accept-Language :
// EN: "User not found with id: 123"
// FR: "Utilisateur introuvable avec l'id : 123"

// Le frontend affiche directement le message
this.error = err.message;
```

## Ajout d'une Nouvelle Langue

### Backend

1. Créer `messages_xx.properties` dans `backend/src/main/resources/i18n/`
2. Traduire tous les messages

### Frontend

1. Créer `xx.json` dans `frontend/src/assets/i18n/`
2. Traduire tous les messages
3. Ajouter la langue dans `LanguageService` :

```typescript
private readonly SUPPORTED_LANGUAGES = ['en', 'fr', 'xx'];
```

4. Ajouter la traduction du nom de la langue dans tous les fichiers :

```json
{
  "language": {
    "xx": "Nouvelle Langue"
  }
}
```

## Ajout de Nouvelles Clés de Traduction

### Backend

1. Ajouter la clé dans tous les fichiers `messages*.properties`

```properties
# messages_en.properties
new.message.key=English message

# messages_fr.properties
new.message.key=Message français
```

2. Utiliser dans le code :

```java
String message = messageSource.getMessage("new.message.key", null, locale);
```

### Frontend

1. Ajouter la clé dans tous les fichiers JSON

```json
// en.json
{
  "section": {
    "new_key": "English translation"
  }
}

// fr.json
{
  "section": {
    "new_key": "Traduction française"
  }
}
```

2. Utiliser dans les templates :

```html
{{ 'section.new_key' | translate }}
```

## Bonnes Pratiques

### Backend

- ✅ Utiliser des clés descriptives : `error.user.not.found` au lieu de `err1`
- ✅ Grouper par contexte : `validation.user.*`, `error.user.*`, `success.user.*`
- ✅ Toujours fournir un fallback par défaut
- ✅ Utiliser des paramètres pour les valeurs dynamiques : `{0}`, `{1}`
- ✅ Tester avec différentes locales

### Frontend

- ✅ Utiliser des clés structurées : `users.title`, `auth.login`
- ✅ Grouper par feature : `users.*`, `auth.*`, `common.*`
- ✅ Préférer les traductions statiques (pipe) aux traductions dynamiques (service)
- ✅ Toujours fournir les traductions pour toutes les langues en même temps
- ✅ Utiliser des paramètres pour les interpolations : `{{username}}`

## Tests

### Backend

```java
@Test
void shouldReturnLocalizedMessage() {
    Locale.setDefault(Locale.FRENCH);
    String message = messageSource.getMessage(
        "error.user.not.found",
        new Object[]{"123"},
        LocaleContextHolder.getLocale()
    );
    assertEquals("Utilisateur introuvable avec l'id : 123", message);
}
```

### Frontend

```typescript
it('should translate messages', () => {
  translate.use('fr');
  expect(translate.instant('auth.login')).toBe('Connexion');

  translate.use('en');
  expect(translate.instant('auth.login')).toBe('Login');
});
```

## Dépannage

### Backend : Messages non traduits

```
Problème : Les messages s'affichent en anglais même avec Accept-Language: fr-FR

Solutions :
1. Vérifier que messages_fr.properties existe
2. Vérifier l'encodage UTF-8 du fichier
3. Redémarrer l'application pour recharger les messages
4. Vérifier les logs Spring au démarrage
```

### Frontend : Traductions manquantes

```
Problème : [object Object] ou clé affichée au lieu de la traduction

Solutions :
1. Vérifier que le fichier JSON est valide
2. Vérifier que la clé existe dans tous les fichiers de langue
3. Ouvrir la console pour voir les erreurs ngx-translate
4. Vérifier que TranslateModule est importé dans le composant
```

### Accept-Language non envoyé

```
Problème : Le backend reçoit toujours la langue par défaut

Solutions :
1. Vérifier que languageInterceptor est configuré dans app.config.ts
2. Vérifier l'ordre des intercepteurs (language avant error)
3. Inspecter les requêtes HTTP dans DevTools > Network
```
